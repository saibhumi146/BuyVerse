components
1) class based   2) function based 
A Class Component is created using a JavaScript class and it extends React.Component.
It was the traditional way of writing components before React Hooks were introduced.

import React, { Component } from "react";

class Welcome extends Component {
  render() {
    return (
      <h1>Hello World</h1>
    );
  }
}

export default Welcome;

function based :(mostly used)
A Function Component is simply a JavaScript function that returns JSX.

After React Hooks, function components can also use state and lifecycle features.

Basic Syntax
function Welcome() {
  return <h1>Hello World</h1>;
}

export default Welcome;
| Feature           | Class Component       | Function Component  |
| ----------------- | --------------------- | ------------------- |
| Syntax            | ES6 class             | JavaScript function |
| State             | this.state            | useState hook       |
| Lifecycle methods | componentDidMount etc | useEffect hook      |
| Code length       | More code             | Less code           |
| Modern usage      | Less used now         | Recommended         |


#componentDidMount

constructor → render → componentDidMount
🤔 Why does render() run BEFORE componentDidMount()?
🧠 Simple Reason:

👉 React must first create and show the UI, then run side-effects.

🔍 Step-by-step flow:
1️⃣ render() runs first
React builds the UI (Virtual DOM)
Converts it to real DOM
Displays it on the screen

👉 At this point, the component is visible

2️⃣ componentDidMount() runs after
Now the component is fully loaded in the DOM
Safe to:
Fetch data
Access DOM elements
Start timers
💡 Why not run componentDidMount() before render?

Because:

❌ DOM does not exist yet
❌ No UI to update
❌ Cannot safely manipulate elements

👉 Example:

document.getElementById("myDiv")

This would fail before render, because the element isn’t created yet.

🔥 Real-life analogy

Think of building a house 🏠:

render() → Build the house (walls, structure ready)
componentDidMount() → Move in furniture, decorate, install WiFi

👉 You can’t decorate before the house exists!

⚙️ Important Insight

React separates:

Step	Purpose
render()	UI creation (pure)
DidMount	Side effects (impure)

👉 This keeps React fast, predictable, and efficient

🎯 One-line answer (for exams/interviews)

render() runs first to generate and display the UI, and componentDidMount() runs afterward to perform side effects once the DOM is ready.

React lifecycle model is the process through which a component is created, updated, and removed from the DOM.


1️⃣ componentDidMount() – First Time Loading
Easy Theory

componentDidMount() runs after the component appears on the screen for the first time.

👉 It runs only once.

Real-Life Example

Think about opening a shopping app.

You open the app
The product page appears
Then products are loaded from the server

👉 Loading products after opening the page is like componentDidMount().

Simple Code Example
componentDidMount() {
  console.log("Page loaded");
}
2️⃣ Component Update (Updating Phase)
Easy Theory

A component updates when its data (state or props) changes, and React re-renders the UI.

Real-Life Example

In a shopping website:

You click Add to Cart
Cart number increases
Page updates

👉 This change is component update.

3️⃣ componentDidUpdate()
Easy Theory

componentDidUpdate() runs after the component updates.

👉 It happens after state or props change.

Real-Life Example

In a shopping cart:

You add a product
Cart number changes
React updates UI
After update → componentDidUpdate() runs

Example use:

Show notification
Save data
Example Code
componentDidUpdate() {
  console.log("Component updated");
}
4️⃣ componentWillUnmount()
Easy Theory

componentWillUnmount() runs when a component is about to be removed from the screen.

Real-Life Example

Imagine a music player page.

Music is playing
You leave the page
Music stops

👉 Stopping the music is like componentWillUnmount().

Example Code
componentWillUnmount() {
  console.log("Component removed");
}
🔄 Very Easy Lifecycle Story

Think of a mobile app screen:

1️⃣ Screen opens → componentDidMount
2️⃣ User clicks something → Component Update
3️⃣ Page refreshes with new data → componentDidUpdate
4️⃣ User closes page → componentWillUnmount

🧠 Super Short Exam Version
componentDidMount: Runs after the component is first displayed.
Component Update: Happens when state or props change.
componentDidUpdate: Runs after the component updates.
componentWillUnmount: Runs before the component is removed.

 Props Drilling: Passing props through multiple components that don't need them just to reach a nested component.

useContext: A React Hook that allows components to access shared data directly, avoiding unnecessary prop drilling.


Props Drilling vs useContext — Structured Notes
1. Props Drilling
Definition

Props drilling is the process of passing data from a parent component to a deeply nested child component through intermediate components that do not use the data themselves.

Why It Happens

React components can only pass data directly to their immediate children using props.

Example
function App() {
  const user = "Sai";

  return <Parent user={user} />;
}

function Parent({ user }) {
  return <Child user={user} />;
}

function Child({ user }) {
  return <h1>Hello {user}</h1>;
}
Flow
App
 ↓ user
Parent
 ↓ user
Child
Problems with Props Drilling
Repetitive prop passing
Makes code harder to maintain
Intermediate components receive unnecessary props
Difficult to manage in large applications
Advantages
Simple and explicit
Easy to track data flow
Suitable for small component trees
When to Use
Small applications
Data needed by only a few components
Shallow component hierarchy
2. useContext
Definition

useContext is a React Hook that allows components to access shared data directly from a Context without passing props through every level.

Purpose

To avoid prop drilling and provide global/shared data to multiple components.

Step 1: Create Context
import { createContext } from "react";

export const UserContext = createContext();
Step 2: Provide Data
<UserContext.Provider value="Sai">
  <App />
</UserContext.Provider>
Step 3: Consume Data
import { useContext } from "react";

const user = useContext(UserContext);

return <h1>Hello {user}</h1>;
Flow
UserContext
     ↓
   Child

No need for:

App → Parent → Child
Advantages
Eliminates prop drilling
Cleaner component hierarchy
Easier state sharing
Better code readability
Disadvantages
Can cause unnecessary re-renders if overused
Not ideal for very complex state management
Can make data flow less obvious
When to Use
Theme management
Authentication/User data
Language settings
Global application settings


Redux Toolkit Notes (Simple Language)
What is Redux Toolkit?

Redux Toolkit (RTK) is the official and easier way to use Redux.

It helps us manage global state in a React application.

Instead of passing data from parent → child → grandchild using props, Redux stores data in one central place called the Store.

Why use Redux Toolkit?

Imagine an e-commerce website.

You add items to a cart from different pages.

Many components need access to the cart data.

Without Redux:

Props drilling becomes difficult.
State management becomes messy.

With Redux Toolkit:

Cart data is stored in one place.
Any component can access it.
Easier to maintain large applications.
Redux Toolkit Flow
Component
   ↓
Dispatch Action
   ↓
Reducer
   ↓
Store Updated
   ↓
UI Re-renders

Example:

Add to Cart Button Clicked
        ↓
dispatch(addItem())
        ↓
Reducer updates cart
        ↓
Store updates
        ↓
Navbar Cart Count updates automatically
Main Concepts
1. Store

The store is the central place where all application data is stored.

Example:

const store = configureStore({
  reducer: {
    cart: cartSlice.reducer,
  },
});

Think of Store as:

Store
 └── Cart Data
 └── User Data
 └── Product Data
2. Slice

A slice contains:

State
Reducers
Actions

Example:

const cartSlice = createSlice({
  name: "cart",
  initialState: {
    items: [],
  },
  reducers: {
    addItem: (state, action) => {
      state.items.push(action.payload);
    },
  },
});
3. Initial State

Initial state is the default state.

initialState: {
  items: []
}

Initially cart is empty.

4. Reducer

Reducers update the state.

Example:

addItem: (state, action) => {
  state.items.push(action.payload);
}

When an item is added:

Old State
[]

After adding:

[
  { id: 1, name: "Pizza" }
]
5. Action

Action tells Redux what needs to happen.

Example:

dispatch(addItem(product))

Action:

ADD_ITEM

with data:

product
6. Dispatch

Dispatch sends an action to Redux.

Example:

dispatch(addItem(item))

Meaning:

"Hey Redux, add this item to cart."
7. useDispatch()

Used to dispatch actions from components.

import { useDispatch } from "react-redux";

const dispatch = useDispatch();

dispatch(addItem(item));
8. useSelector()

Used to read data from the store.

const cartItems = useSelector(
  (store) => store.cart.items
);

Now you can access cart data anywhere.

Cart Example
Add Item
dispatch(addItem(product));

Reducer:

addItem: (state, action) => {
  state.items.push(action.payload);
}
Remove Item
removeItem: (state) => {
  state.items.pop();
}
Clear Cart
clearCart: (state) => {
  state.items.length = 0;
}

or

clearCart: () => {
  return { items: [] };
}
Provider

Provider makes Redux available to the entire application.

<Provider store={appStore}>
  <App />
</Provider>

Without Provider:

useSelector()
useDispatch()

will not work.
