components
1) class based   2) function based 
A Class Component is created using a JavaScript class and it extends React.Component.
It was the traditional way of writing components before React Hooks were introduced.

import React, { Component } from "react";

class Welcome extends Component {
  render() {
    return (
      <h1>Hello World</h1>
    );
  }
}

export default Welcome;

function based :(mostly used)
A Function Component is simply a JavaScript function that returns JSX.

After React Hooks, function components can also use state and lifecycle features.

Basic Syntax
function Welcome() {
  return <h1>Hello World</h1>;
}

export default Welcome;
| Feature           | Class Component       | Function Component  |
| ----------------- | --------------------- | ------------------- |
| Syntax            | ES6 class             | JavaScript function |
| State             | this.state            | useState hook       |
| Lifecycle methods | componentDidMount etc | useEffect hook      |
| Code length       | More code             | Less code           |
| Modern usage      | Less used now         | Recommended         |


#componentDidMount

constructor → render → componentDidMount
🤔 Why does render() run BEFORE componentDidMount()?
🧠 Simple Reason:

👉 React must first create and show the UI, then run side-effects.

🔍 Step-by-step flow:
1️⃣ render() runs first
React builds the UI (Virtual DOM)
Converts it to real DOM
Displays it on the screen

👉 At this point, the component is visible

2️⃣ componentDidMount() runs after
Now the component is fully loaded in the DOM
Safe to:
Fetch data
Access DOM elements
Start timers
💡 Why not run componentDidMount() before render?

Because:

❌ DOM does not exist yet
❌ No UI to update
❌ Cannot safely manipulate elements

👉 Example:

document.getElementById("myDiv")

This would fail before render, because the element isn’t created yet.

🔥 Real-life analogy

Think of building a house 🏠:

render() → Build the house (walls, structure ready)
componentDidMount() → Move in furniture, decorate, install WiFi

👉 You can’t decorate before the house exists!

⚙️ Important Insight

React separates:

Step	Purpose
render()	UI creation (pure)
DidMount	Side effects (impure)

👉 This keeps React fast, predictable, and efficient

🎯 One-line answer (for exams/interviews)

render() runs first to generate and display the UI, and componentDidMount() runs afterward to perform side effects once the DOM is ready.

React lifecycle model is the process through which a component is created, updated, and removed from the DOM.


1️⃣ componentDidMount() – First Time Loading
Easy Theory

componentDidMount() runs after the component appears on the screen for the first time.

👉 It runs only once.

Real-Life Example

Think about opening a shopping app.

You open the app
The product page appears
Then products are loaded from the server

👉 Loading products after opening the page is like componentDidMount().

Simple Code Example
componentDidMount() {
  console.log("Page loaded");
}
2️⃣ Component Update (Updating Phase)
Easy Theory

A component updates when its data (state or props) changes, and React re-renders the UI.

Real-Life Example

In a shopping website:

You click Add to Cart
Cart number increases
Page updates

👉 This change is component update.

3️⃣ componentDidUpdate()
Easy Theory

componentDidUpdate() runs after the component updates.

👉 It happens after state or props change.

Real-Life Example

In a shopping cart:

You add a product
Cart number changes
React updates UI
After update → componentDidUpdate() runs

Example use:

Show notification
Save data
Example Code
componentDidUpdate() {
  console.log("Component updated");
}
4️⃣ componentWillUnmount()
Easy Theory

componentWillUnmount() runs when a component is about to be removed from the screen.

Real-Life Example

Imagine a music player page.

Music is playing
You leave the page
Music stops

👉 Stopping the music is like componentWillUnmount().

Example Code
componentWillUnmount() {
  console.log("Component removed");
}
🔄 Very Easy Lifecycle Story

Think of a mobile app screen:

1️⃣ Screen opens → componentDidMount
2️⃣ User clicks something → Component Update
3️⃣ Page refreshes with new data → componentDidUpdate
4️⃣ User closes page → componentWillUnmount

🧠 Super Short Exam Version
componentDidMount: Runs after the component is first displayed.
Component Update: Happens when state or props change.
componentDidUpdate: Runs after the component updates.
componentWillUnmount: Runs before the component is removed.

Lazy Loading and Suspense hooks

Q1. What is lazy loading?
Loading components only when needed.

Q2. Why use Suspense?
To display fallback content while lazy components load.

Q3. What is code splitting?
Breaking bundle into smaller chunks.

Q4. Which function is used for lazy loading?
React.lazy()

const Dashboard = React.lazy(() => import("./Dashboard"));

<Route
 path="/dashboard"
 element={
   <Suspense fallback={<h1>Loading...</h1>}>
      <Dashboard />
   </Suspense>
 }
/>
Advantages of Lazy Loading
Faster Initial Load
Only necessary files are downloaded first.
Better Performance
Less JavaScript at startup.
Reduced Bundle Size
Code splitting happens automatically.
Better User Experience
App feels faster.

CUSTOM HOOKS 

Custom Hooks in React
A Custom Hook is a JavaScript function that:
Uses React hooks internally
Starts with the word use
Helps reuse logic between components

A custom hook:looks like

Uses built-in hooks like:
useState
useEffect
useContext
Returns reusable data/functions
Components use the returned values

Advantages of Custom Hooks
Reusable Logic
Write once, use anywhere.

Cleaner Components
UI code stays separate from logic.
Better Maintainability
Easy to update logic in one place.
Reduces Duplication
Avoid repeating same code.
